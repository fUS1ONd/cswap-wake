# cswap-wake

[English version](README.md)

Запускает 5-часовые окна лимитов на **всех** аккаунтах Claude Code с разносом по времени и не трогает активный аккаунт.

Claude Code считает расход в 5-часовых окнах, которые стартуют с первого сообщения. Если окно уже идёт к тому моменту, когда садишься работать, оно раньше сбросится, и свежий лимит придёт раньше. `claude-wake` пишет короткое «qq» каждому аккаунту из [claude-swap](https://github.com/realiti4/claude-swap) (`cswap`), как только его окно закрылось. Аккаунты разнесены на 30 минут, чтобы лимиты не сбрасывались все разом.

## Как работает

Крон запускает `claude-wake` каждую минуту. Почти всегда скрипт только читает файл состояния и выходит.

Когда подходит срок пинга аккаунта:

| Состояние аккаунта (из `cswap list --json`) | Действие | Следующая проверка |
|---|---|---|
| окно 5h уже открыто (сам работал или переключил автосвитч) | пинга нет | сброс окна + 1 мин |
| недельный лимит выбран на 100% | пинга нет | недельный сброс + 1 мин |
| окна нет | `cswap run N -- -p "qq"` (пустой контекст, ~540 токенов) | сейчас + 5 ч 1 мин |
| пинг упал | — | повтор через 15 мин |

- **Сколько угодно аккаунтов.** Новые аккаунты `cswap` подхватываются в течение 30 минут и встают в ближайший свободный 30-минутный слот. Удалённые забываются, отключённые через `cswap disable` пропускаются.
- **Аккаунт определяется по email и организации**, поэтому `cswap swap` и `cswap move` расписание не путают.
- **Активный аккаунт не меняется.** Пинг идёт через `cswap run` в отдельном профиле сессии, так что запущенные сессии Claude Code остаются на своих аккаунтах.
- **По одному за раз.** Если к сроку подошли несколько аккаунтов (например, после простоя), пинг уходит одному, остальные сдвигаются по 30 минут.
- **Переживает перезапуски.** Состояние хранится в `~/.local/state/claude-wake/state.json`, lock-файл не даёт тикам наложиться.

## Требования

- Linux или macOS с cron
- Python 3.9+ (только стандартная библиотека)
- [Claude Code](https://docs.claude.com/en/docs/claude-code) (`claude` в `PATH`)
- [claude-swap](https://github.com/realiti4/claude-swap) с добавленными аккаунтами (`cswap add`)

## Установка

```bash
curl -fsSL https://raw.githubusercontent.com/fUS1ONd/cswap-wake/main/claude-wake -o ~/.local/bin/claude-wake
chmod +x ~/.local/bin/claude-wake
```

Добавить в `crontab -e`. У крона урезанный `PATH`, поэтому передаём тот, где лежат `claude` и `cswap`:

```cron
* * * * * env HOME=$HOME PATH=$HOME/.local/bin:/usr/local/bin:/usr/bin:/bin $HOME/.local/bin/claude-wake >> $HOME/claude-wake.log 2>&1
```

## Использование

```bash
claude-wake status   # расписание: кому и когда следующий пинг (MSK)
claude-wake          # один тик, то же, что делает крон
```

Пример лога:

```
[claude-wake 2026-10-20 09:01 UTC] новый аккаунт a@example.com, первый пинг 2026-10-20T09:01:01+00:00
[claude-wake 2026-10-20 09:01 UTC] Account-1 a@example.com: ok «Привет!», следующий раз 2026-10-20T14:02:01+00:00
[claude-wake 2026-10-20 10:01 UTC] Account-3 c@example.com: окно уже открыто, следующий раз 2026-10-20T13:01:00+00:00
```

## Настройка

| Переменная | По умолчанию | |
|---|---|---|
| `CLAUDE_WAKE_PROMPT` | `qq` | текст пинга; подойдёт любое короткое сообщение, главное — дойти до модели |
| `CLAUDE_WAKE_MODEL` | `claude-haiku-5-5` | модель для пинга; окно открывает любая, хватает самой дешёвой |

Константы в начале скрипта:

| Константа | По умолчанию | За что отвечает |
|---|---|---|
| `CYCLE` | 5 ч 1 мин | через сколько после удачного пинга писать снова; окно длится 5 ч, лишняя минута — чтобы пинг пришёлся после сброса |
| `STEP` | 30 мин | разнос между аккаунтами, чтобы лимиты не сбрасывались все разом |
| `GRACE` | 1 мин | запас после сброса окна или недельного лимита, прежде чем писать аккаунту |
| `RETRY` | 15 мин | через сколько повторить упавший пинг |
| `DISCOVERY` | 30 мин | как часто перечитывать cswap: новые, удалённые, отключённые аккаунты |
| `STATE_DIR` | `~/.local/state/claude-wake` | где лежат расписание (`state.json`) и lock-файл |

Новый `STEP` действует на новые слоты; уже расписанные в `state.json` пинги придут по старому графику, и за один цикл разнос выровняется. Чтобы спланировать всё заново, удали `state.json`.
